So whereas in the last lesson, we were looking at local implementations of using Git and Version Control, in this lesson, we&#x27;re going to talk about how you can create a Remote Repository. So a repository that&#x27;s hosted on somebody else&#x27;s server or somebody else&#x27;s computer by using GitHub. Now, most people would have heard of GitHub and certainly by now you would have used GitHub many times. So if you haven&#x27;t yet set up an account on GitHub, then this is the time to do it. So head over to github.com and simply fill out this quick form to create an account on GitHub. It&#x27;s completely free, and all you need to do is just confirm your email so that you can access it. Once you&#x27;ve done that, go ahead and sign in. Once you&#x27;ve signed in, you should be looking at this page. And what we&#x27;re going to do is we&#x27;re going to create a repository inside the browser-based GitHub. So if you navigate to this top right corner and click that plus arrow (+), then you can select New repository and I&#x27;m going to call my repository, same name, I guess we&#x27;ll call it, &quot;Story&quot; and let&#x27;s give it a description. Let&#x27;s say, &quot;My masterpiece.&quot; Now, by default, all repositories that you create on GitHub are Public. That means that anyone can see all of the files inside your saved repository. So everything that you commit to your remote repository or to your GitHub repository will be public. If you don&#x27;t want that, then you can select Private, but in most cases, if you&#x27;re not doing anything that&#x27;s top secret, or if you&#x27;re not developing technology that is completely brand new, then having a public repository is not such a big problem. And on the other hand as well, you can see loads of other people&#x27;s public repositories and you can see, for example, how they structure their code, what is their style, and you can see how people do things. For example, on GitHub, there are whole repositories on things like flappy bird. So it&#x27;s the entire implementation of flappy bird and you can run it or you can also look through their code base to see how they did this. This is the beauty of open-source code, and as you develop in your journey of becoming a developer, then you might find that you want to contribute to other open source projects, help them out a bit and work in a virtual team to try and contribute your knowledge and your programming skills. Okay, so once I&#x27;ve selected public, the next thing is that I&#x27;m going to leave this part empty. I&#x27;m not going to initialize a README for my repository just yet. The next thing is that I&#x27;m going to go ahead and click the big green button and create my repository. Now, you can see that there are two ways that they tell you, you can set up your repository. You can either set it up in GitHub on desktop, their desktop client, which I am not a big fan of, but instead what we&#x27;re going to do is we&#x27;re going to use the command line instructions to set up our repository. So we are going to push an existing repository that we&#x27;ve got locally onto this remote repository. And to do that we need to copy the address of our GitHub repository and we&#x27;re going to use these two lines of code in order to transfer or push our existing local repository from the command line. All right. I&#x27;m currently inside my Story directory, which also happens to be the Working directory for this particular project. And here I am going to again take a look at &quot;git log&quot; to see what previous commits we&#x27;ve got. And you can see that we&#x27;ve got two previous commits and I would like to push both of these commits onto GitHub. To do that, the first thing is creating a Remote. So it&#x27;s telling my Local Git Repository that I&#x27;ve created a Remote Repository somewhere on the internet and I want to transfer all of my commits over there. So the command that we&#x27;re going to use is, &quot;git remote add origin&quot;. Now, origin is simply the name of your remote and you can theoretically call it anything you want. You can call it bacon if you want, but by convention and it&#x27;s highly recommended that you simply keep the name origin. And the reason is because most programmers are used to the conventional naming, and that means it will be much easier for them to understand what&#x27;s going on in your project when they have a look at it, instead of you doing something completely different, which will be very surprising and it&#x27;ll be a lot harder for people to understand what&#x27;s going on. So, &quot;git remote add origin&quot;, and then we&#x27;re going to paste the URL of our remote repository on GitHub, and then we&#x27;re going to go ahead and hit Enter. And now that remote is created, so we can push our local repository onto our Remote Repository, which is called origin. So we&#x27;re going to say, &quot;git push -u origin main&quot;. And what this line of code does is that it pushes your local repository to the remote repository using the u flag or the u option, which basically links up your remote and your local repositories. And then we&#x27;re going to push it towards the remote that&#x27;s called origin, and we&#x27;re going to push it to the branch that&#x27;s called main. The main branch is simply the default branch or the main branch of all of your commits. And later on when we cover branching, then we&#x27;re going to talk more about what is a main and what is a branch. But for now, we&#x27;re just saying that we&#x27;re going to push our local repository onto this origin remote and we&#x27;re going to push it to the main branch. So let&#x27;s go ahead and hit Enter. And there&#x27;s going to be a little bit of work being done in the background, because it&#x27;s actually going to have to upload your local repository to the remote repository on GitHub servers, and depending on the size of your local repository, this can take various amounts of time. Now, once we see our prompt, so the flashing cursor, or the dollar sign, that means that our push is successful, and as you can see, it says, &quot;branch main set up to track remote branch main from origin.&quot; Sounds really confusing, but if you head back over to GitHub and if you&#x27;re on the same page, all you have to do is hit command R to refresh or just press the refresh button and you can see that all of our files are now hosted on GitHub and it&#x27;s complete with all of our commit messages. So if you go into Insights, and go into Network, you can actually see our main branch, which currently only has two save points or two commits. And if you hover over them, you can actually see the commit messages of each of these. As you build out your project, as you add more commits either locally or pushing it remotely or probably doing both, then you can see the progress of your files in your GitHub repository. So now you can see all of the code, if it&#x27;s code file, or in our case, it&#x27;s just a text file hosted on GitHub and you can point anybody towards this. And there are actually cases where people do a lot of story writing using GitHub just because it&#x27;s so good at tracking your save points and being able to revert to previous versions in the past. So for example, if you head over back to the main page and you go to your commits, you can see both of those commits when they were committed, and also if you click on it, you can see the changes that were made at those time points. So if we have a look at chapter 1, you can see this is all we had at the point when we made our first commit. Previously, we said that we have a Working directory, which is the directory where we initialized git. Then we can push our files to a Staging area where we can pick and choose which files we want to commit. Then once we&#x27;re ready, then we can commit our files or our save point to our Local repository. So once you&#x27;ve done a few commits, then you actually have this timeline of various commits and this is called your Main Branch. So the main branch is your main branch of commits or save points, and it is sequential, and this is usually where your main progress is saved or committed. Later on, we then introduced this idea of the Remote Repository. The important thing to note is that you can have a local repository completely in parallel with a remote repository check the differences between them, but you can also sync them or push things from your local repository to your remote repository. So in our case, the local repository is the git file that we&#x27;ve got inside our Story directory, and the remote repository is GitHub, which hosts our code and also hosts all of the changes that were made in between the different commits. So we have this main branch of various commits; first commit, second commit, third commit in our local git repository, and when we performed the command &quot;git push&quot;, then that effectively pushed all of those commits, all of those various versions and changes, and code pieces to our remote repository on GitHub. So that&#x27;s what &quot;git push&quot; does.
