Now, normally we use the distance method to check what is the distance between the ball and the paddle. We get our ball and we check its distance from the paddle. Now remember that our ball has a width of 20 pixels and our paddle has a width of 20 pixels. Normally we would say, well, if that distance between the two of them is less than 20, well, then they&#x27;ve probably made contact, right? But the problem occurs when the ball hits the paddle, not right in the center, but at the edge of the paddle, because this distance measures the center of the ball from the centre of the paddle as the distance. So you can see that this distance is way bigger than 20, so it&#x27;s not going to register as a collision. How can we solve this problem? Well, we could add on an additional condition. We could check well if the ball has gone past a certain point on the X-axis, if it&#x27;s gone far enough over to the right and it&#x27;s within a 50 pixel distance of the paddle, then that also means it&#x27;s made contact with the paddle. Inside our main.py I&#x27;m going to add a comment to detect collision with right paddle. So let&#x27;s experiment with some numbers here and see if we can get the ball to bounce off the paddle. In this case, we&#x27;re going to check if the ball.distance to the r_paddle is less than 50 and the ball.xcor is greater than 340. If the ball has hit the right paddle, let&#x27;s print something to the console to test our code. Let&#x27;s print made contact. So if we run this code and I manage to make contact with the ball, you can see that it says &#x27;Made contact&#x27; in our console. So instead of just printing made contact, what we want the ball to do is to again, to bounce. Now, this bounce is a little bit different from the last bounce, because the previous one was changing its Y coordinate so that it moved in the opposite along the vertical. But in this case, we actually want it to move along the opposite direction in the horizontal because the paddle is here and the ball is coming this way, we want it to go back this way. So instead of just calling this bounce, I&#x27;m going to right-click on it and then refactor and rename to bounce_ y because this is bouncing in the Y-axis. And then when our collision is detected, we&#x27;re going to get the ball to bounce in the X direction. So now if we run our code, you can see that even though this only works on the right paddle, when the ball hits the right paddle it moves back and it bounces back towards the left. It changes the direction that it was moving in the X-axis. So now lets add the collision for both paddles because they both need to bounce in the X-axis and so we&#x27;re going to tag onto this a &#x27;or&#x27; statement and we&#x27;re going to say or if the ball.distance to the left paddle is also less than 50 and on top of that the ball.xcor is less than -340.
