Lecture: Programming is not Memorising
----------------------------------------

Hey, you've reached a big milestone. Today you've completed 20 days of code. Now that is a fifth of the way and that's massive. If you're not already, you should be really patting yourself on the back because you've done really well. Now, today, the thing I want to talk about is a question that students often have, which is, "Hey, you know, I've gone to day 20. But when I look back at the stuff that I did on day one, I can't remember exactly the names of the functions or how to write out the syntax for a particular piece of code. Does that mean that I haven't learned anything?" And the analogy that I like to give is, have you ever played video games, especially video games, where they require, like, complex combinations that you have to remember, like streetfighter? You know, how in order to do like a particular move, you need to be able to do up, up, down, down, X, Y, a, b. Now, when you're doing it in that moment, when you've just learned it, you remember how to do it. But when you come back to it in a month, you're like, "Oh, I don't remember those combinations. Does that mean that I haven't learned anything?" Well, the point is that programming is not about memorizing because we're in a day and age where information is cheap. You can search Google for any piece of information you want and it's there within a second. What your job needs to be is to understand how things work. Make sure that you understand how to use the code, when to use it, how it works behind the scenes. That way, the next time when you need to use it and you've forgotten how to write the syntax, you can just Google it, look it up. And as soon as you see it, you'll remember "Oh yeah, that's it. I know how to use it." So don't worry about memorizing things. Focus on understanding the code. So, good luck and keep going.
