### Summary

Now that we&#x27;ve seen how HTML elements and tags work, it&#x27;s time to explore the bigger picture, what&#x27;s called the HTML Boilerplate. And this will allow us to understand the structure of our HTML files just like how there is structure to letters that you would write. For example, there&#x27;s the section where you have your address and then you probably would include a Dear so and so, and then you have the body of your letter and finally you would write something like, &quot;Yours sincerely&quot; and then your name and signature. Similarly, there is a structure to our HTML files and it looks something like this. And this is called a Boilerplate. It&#x27;s what you usually start off with when you create any new HTML file. And we&#x27;re going to go through it line by line so that we understand it. At the top of every HTML file, there should be a &quot;Doctype declaration.&quot; And that&#x27;s what this tag does. It tells the browser which version of HTML the file was written in. Now the latest version of HTML is HTML5 and the Doctype declaration looks like this with an angle bracket (&lt;), an exclamation mark(!), DOCTYPE in all caps and then html. And this line tells any browser that&#x27;s reading our HTML file that we have written our code in HTML Version 5. The next part that we&#x27;ve got is the actual &quot;html&quot;. Now, this is going to be the &quot;root&quot; of the document. It means that everything else, every other element, no matter if it&#x27;s an h1 or an image or a link, it&#x27;s all going to go inside the opening and closing tags of the html element. And this attribute where it says &quot;lang,&quot; this is the language of the text content in that element. So for example, if you&#x27;re writing a website that is going to be targeted at English speakers, then you&#x27;re going to set your lang to English, &quot;en&quot;. Now this isn&#x27;t very important for the users who can see your website, it&#x27;s more important for the users who can&#x27;t, because there are various screen readers and assistive technologies that will look at this language attribute so that when they read out the website, they can pronounce the words correctly. &quot;Opens profile photo. Follow @yu_angela. Button.&quot; Now, with the HTML element, we&#x27;re starting to see the beginnings of a hamburger. There&#x27;s a bun at the top and there&#x27;s a bun at the bottom. For those of you guys who have been my longterm friends, you know how much I love food analogies, but this is a great one because when we have an html element, usually there is the opening and the closing and everything that belongs in it is sandwiched inside. Now the next part of the HTML boilerplate is the &quot;head element&quot;. And this is an area where important information about our website is placed that is not going to be displayed to the user. It includes things that will help the website render in the browser correctly, but it doesn&#x27;t include any sort of content like text or images or anything that the user will see. So one of the things that you should always have in the Head Section is a &quot;meta&quot; tag for the character set encoding of the web page, and in this case, it&#x27;s set as &quot;UTF-8&quot;. What this does is it ensures that the characters that you&#x27;re using on your website gets displayed correctly. So, for example, in certain character sets, it won&#x27;t allow emojis to render, in other character sets they won&#x27;t have certain symbols like multiplication and division symbols, and that&#x27;s what this &quot;meta&quot; tag takes care of. Usually by convention in our HTML boilerplate, we will simply just include this tag as is using the &quot;UTF-8&quot; character set, which is one of the most common. So you don&#x27;t even have to think about it. Now another thing that you should have in your Head Section is the &quot;title&quot; of your website, and that title is usually what gets displayed up here in the tab bar. And in fact, if you right-click on any website in Chrome, you can click to &quot;View Page Source&quot; and you can see we&#x27;ve got our DOCTYPE, we&#x27;ve got our html element, inside it, we&#x27;ve got our head, our character set. And then if we scroll a little bit more, you can see we&#x27;ve got our title here. And in between the opening and closing tags of the title, it tells you what title should be displayed up here. So in our case here, the title will simply say, &quot;My Website.&quot; Now, there&#x27;s a lot more things that can go into the head element, as you&#x27;ve seen when we looked at the Google home page, but for now, these two are the most important things that will always go into your HTML files and it&#x27;s important to know. We&#x27;ll cover other tags as we come across them. Now, the next sandwich inside the sandwich, if you will, are two slices of tomatoes. No, just kidding. It&#x27;s actually the &quot;body element.&quot; Just like a person, after the head element comes the &quot;body&quot; element. Inside the body element is where we&#x27;re going to be spending the majority of our time creating and writing our website. This is where all of the content of the website goes. So the text, the titles, the images, the links, everything that you can do with HTML, creating content and structure goes in between the opening and the closing tags of the body element. So somewhere inside here. Now what can go in here? Well, we&#x27;ve seen already how an h1 works so we can put in a heading, we can add images, we can add lots of things, and this is essentially where the meat of our website is going to live. Once our burger collapses down, you can see that this is what a typical website&#x27;s HTML code is made up of. So no matter what you add into your body, you can vary it up, but by default, most websites will start off with a boilerplate that looks like this. When you&#x27;re starting out, I often recommend students to type this out when they&#x27;re creating new websites and in fact you can have a go doing this now by going into VS Code, typing out these elements and creating your website entirely from scratch. Now, we&#x27;re beginning to see this idea of nesting in an HTML document, and this is going to be a concept that&#x27;s going to become super important as we learn more and more programming, but it&#x27;s simple to understand if we come back to this analogy of the hamburger. So we have our HTML element which has the opening and closing tags here, and it is exactly like our hamburger bun. So this is our top bun and this is our bottom bun, and sandwiched in between is everything that goes inside the HTML element. Now, if we take a look at our body element, then you can see here we&#x27;ve got the opening body tag, which will represent with a slice of tomato and the closing body tag, and in between those two slices of tomato is the content for our website. Now, you&#x27;ll notice that some of the HTML tags, even though they have an opening and closing tag, they&#x27;re not on different lines. And that&#x27;s because if we can fit it on one line and we can see the beginning and the end very easily, then we don&#x27;t actually need to create several lines, but nonetheless, it still got a beginning and an end. Now the important thing for us when we&#x27;re writing code and we&#x27;ve got all of this sandwiching going on that we indent our code properly so that you can see that this clearly lines up with the opening tag here. So they are clearly sandwiching something in between. And then we have two spaces and we&#x27;ve got the next indentation level here. So this one lines up with the closing tag and through this kind of indentation you can quite easily visualize that this Head Section is clearly embedded inside the html section. So just like our lettuce is inside our hamburger, by indenting our code properly, we&#x27;ll be able to keep our code tidy and we&#x27;ll be able to see at a glance exactly what our code looks like. Now, finally, because we&#x27;re using VS Code, I want to tell you about a shortcut, that means you don&#x27;t have to type out this boilerplate every single time. Once you&#x27;ve typed it out once or twice and you know exactly how this boilerplate looks, you can save a lot of time by simply typing exclamation mark (!), hitting Enter on the first selection and then it will automatically insert all of that code for you, saving you a lot of time, especially when you&#x27;re creating many HTML documents. Now, the important thing here, though, is this only works if you have created a dot HTML (.html) website. So notice that when you create a new file inside VS Code, if you name it and save it as something something dot html, then this trick will work. If you save it with another extension, then it won&#x27;t. There&#x27;s a couple of things here that we haven&#x27;t seen before, a couple of more &quot;meta tags&quot; and there&#x27;s a lot of other meta tags, but here we&#x27;ve got one line here which says, http-equiv=&quot;X-UA-Compatible&quot; content=&quot;IE-edge&quot;. This basically just keeps our code compatible with Internet Explorer. And in fact, I normally don&#x27;t write this line anymore because Internet Explorer has been deprecated, and is no longer in use. So if you want to keep your code clean, you can actually delete this from your VS Code autogenerated boilerplate. Now the next one tells you the &quot;viewport,&quot; and it defines how the website should be displayed relative to the screen that it&#x27;s being rendered on. And this line of code just tells the browser how to display your website when it first opens. So now that we&#x27;ve learned all about HTML boilerplates, it&#x27;s time to build your own boilerplate, or in this case, build your own burger. As you&#x27;ve noticed, there are endless numbers of HTML elements and we&#x27;re going to be creating our own HTML elements, but the important thing here I want you to understand is how nesting works in HTML and how you can keep your code tidy by using good indentation and keeping good programming practices. If we&#x27;re building our own imaginary burger, let&#x27;s imagine the world&#x27;s best burger, you can have it vegan, you can have it vegetarian, you can have bacon, you can have whatever it is your heart desires, but you have to write it in HTML code. Let&#x27;s begin by creating a bun. So I&#x27;ve got a bun element that I&#x27;ve created which has an opening and a closing tag, and I&#x27;ve added an attribute. You can add as many of these attributes as you like. And remember, we add attributes by giving it a name, and then after an equal sign, we give it a value. Now the next part is for you to invent. So head over to VS Code and build your own burger, adding in whatever elements you want. Add tomatoes, add ham, but make sure that you&#x27;re keeping the indentation correct and that you&#x27;re working with this idea of opening and closing tags. But you can be as creative as you like, and be sure to share your code for your burger in the Q&amp;A section.
