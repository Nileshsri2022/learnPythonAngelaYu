# Career Action Plan — after 100 Days of Code

Distilled from the Day 84 AMA and the Day 83 portfolio section. Fill in the blanks, set
dates, and treat it like a sprint board.

---

## 1. Where you are

- [ ] 100 Days of Code finished (or nearly)
- [ ] Portfolio projects: 0 / 1 / 2 / 3 built and deployed
- [ ] GitHub profile README set up
- [ ] CV / résumé mentions projects with live links

## 2. The next 30 days

| Week | Goal | Done |
|------|------|------|
| 1 | Pick **one** portfolio project; write its README and sketch its pages/routes | ☐ |
| 2 | Build a working (ugly is fine) version; deploy it | ☐ |
| 3 | Add one feature that wasn't in any course lesson | ☐ |
| 4 | Polish it, get a friend to use it, fix what they break | ☐ |

Then repeat for project two. Two *finished* projects beat six half-built ones.

## 3. Show, don't tell

- [ ] Every project has a live URL, linked at the top of its README
- [ ] Screenshots in the README (recruiters skim)
- [ ] A short "what I learned / what I'd do next" section
- [ ] GitHub profile pinned repos: your best three
- [ ] Commit history that reads like work, not one giant "final commit"

## 4. Build the skills that transfer

- [ ] Read one real job posting a week and note the gaps
- [ ] Practise explaining your code out loud (interviews are conversations)
- [ ] Learn Git workflows properly — branches, PRs, code review (Day 70)
- [ ] Get comfortable reading docs for something you've never used

## 5. Getting hired

* **Think like the hiring manager**: thousands of applications, so evidence beats claims.
* **"So good they can't ignore you"** — pick one area and get visibly good at it.
* Apply *while* you build; each project makes the next application stronger.
* Ask for feedback on rejections; iterate like any other product.

## 6. If you're going freelance instead

- [ ] First clients: charge well below your perceived worth — buy reviews, referrals and
      experience
- [ ] Deliver on time, communicate clearly, over-communicate when stuck
- [ ] Raise prices when you're turning work away (the Day 84 lesson)
- [ ] Keep every project's code; a client's website is a portfolio piece with a testimonial

## 7. Daily habits that actually move the needle

| Habit | Time |
|-------|------|
| Study-with-me focus block (Day 84) | 25–50 min |
| Write one line about what you did | 1 min |
| Read one page of documentation for something unfamiliar | 5 min |
| Commit something to GitHub | whenever you code |

---

## 8. The long game

* Fundamentals outlive frameworks: Python, HTTP, SQL, HTML/CSS, Git.
* Keep a "projects I want to build" list; it never runs out.
* Teach someone else — explaining is the fastest way to find your own gaps.
* Build things you'd use. Motivation follows usefulness.
